video. It establishes pipeline and evidence integrity, **not** metric accuracy
or a semantic/mesh reconstruction claim.

## Procedure

```bash
RAYON_NUM_THREADS=16 ./target/release/vestra reconstruct \
  --video IMG_2269.MOV \
  --model depth-anything-base-f32.gguf \
  --output img-2269.vestra

./target/release/vestra inspect --scene img-2269.vestra
```

The first reconstruction checkpointed all 14 immutable measured windows. Its
strict fusion initially rejected the first seam solely because an arbitrary
relative scale lower bound of `0.1` rejected a well-supported scale of
`0.07178083`: 7,938 direct source-pixel correspondences, 7,890 inliers, and
RMS residual `0.010779493`. This was a product bug: relative multiview scale
has no defensible fixed `0.1…10` range. Vestra `9a78445` changed the gate to
numeric-collapse protection (`1e-3…1e3`) while retaining correspondence,
inlier, residual, finite-geometry, and degeneracy checks. A dedicated unit
test covers a supported `0.05` relative seam.

Fusion was then rerun from the persisted raw windows, without repeating model
inference. Vestra `a000c27` subsequently added deterministic first-observer
ownership: overlapping source frames remain in raw chunks and still establish
seams, but are emitted once into the fused layer rather than casting duplicate
confidence votes. The final report below is from that corrected derivative.

The Studio HTTP server successfully served the scene manifest and its seven
progressive point chunks. The final binary delivery upgrade publishes seven
40-byte surfel segments (12 MB total for this scene); the Studio HTTP contract
was exercised directly against one 2,000,012-byte segment, i.e. a 12-byte
header plus 50,000 records. The browser automation container could not reach
the host-local development port, so this record makes no browser-render
screenshot claim. The Studio's local browser rendering path is separately
covered by the earlier end-to-end smoke.

The diagnostic derivative at `41e4950` rebuilt the fused world from the same
14 immutable measured chunks and exported `159` camera entries as
`vestra.camera/v1` (155 KiB). Each entry keeps the model's W2C calibration in
its original window-local frame and supplies the final local-to-fused relative
Sim(3) transform. That is intentionally composable evidence, not a fabricated
global camera matrix.

Vestra `7f15b08` then ran `reconstruct --resume` against the same video,
model, scene, and locked settings. It validated the source/model/engine/kernel
and settings fingerprints, loaded the checked 504×336 PPM decode cache, reused
all 14 schedule-compatible raw window chunks, performed no model inference,
and reproduced the identical derived fused chunk. This validates continuation
from completed checkpoints; an interruption between windows is covered by the
same atomic per-window publication contract.

Vestra `ce0a3b4` validated CLI cancellation against a disposable copy of the
same real scene. It removed only the decode cache, started
`reconstruct --resume`, sent `SIGINT` during decoding after 200 ms, and got
exit code `130` at 201 ms from process start. The cancellation handler emitted
the resume instruction; the copied manifest still referenced all 14 complete
measured chunks and its existing fused derivative. This is the verified
sub-second CLI cancellation path. It does not claim interruption within an
individual multi-view engine forward; atomic publishing and resume preserve
correctness at that lower boundary.

Vestra `ab2d11d` then served this same bundle through the local Studio host.
The authenticated-by-local-bind `GET /evidence.json` contract returned the
relative-scale marker and exactly `159` finite camera rays, one for each
persisted window-local camera observation. Studio offers the overlay via the
**Show camera rays** control or the `C` key. HTTP and script syntax are
verified here; this record does not make a separate rendered-browser screenshot
claim.

Vestra `886d551` also inspected 26-neighbour voxel topology at the persisted
relative voxel size. The sparse `pixel_stride=8` diagnostic world reports
`191,790` components, largest component `48,459` surfels, and `178,630`
singleton components out of `300,906` total. This is expected for deliberately
thinned independent depth samples and is **not** presented as a mesh
connectedness failure. It establishes a baseline for the future dense/TSDF
de-ghosting fixture and prevents a misleading generic “connected scene” gate.

## Interpretation and remaining gate

- All model windows, durable raw evidence, sequential seams, fusion, and
  progressive delivery completed successfully for real video.
- `ready` is only an adjacent-luma capture-risk signal; it is **not** a
  reconstruction-quality certificate.
- The world remains relative scale. No distance or room dimension is claimed.
- No non-adjacent revisit met the conservative automatic loop-closure gates;
  `pose_graph: null` is correct evidence, not a missing data field.
- The next acceptance run should deliberately include a known revisit and be
  inspected for an accepted loop edge, seam diagnostics, holes/ghosting, and
